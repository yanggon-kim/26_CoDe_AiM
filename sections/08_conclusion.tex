\section{Conclusion}
\label{sec:conclusion}

% P:conc-summary
Skinny GEMMs keep LLM decoding memory-bound on mobile platforms and edge servers, and prior DRAM PIM paces every
multiply--accumulate (MAC) by a DRAM command and fills its idle beats with multipliers or commands. This paper argues
that DRAM timing bounds column accesses, not MACs on a latched column, so a PIM die can fill those beats with clock
cycles instead of multipliers. CoDe decouples MAC timing from DRAM command timing: one column command feeds many
processing-unit beats over a tile of tokens. On LPDDR5-6400, CoDe returns 1.99$\times$ LP-Spec-style's tokens per
second per logic mm$^2$ and decodes 1.60$\times$ faster than LP-Spec-style at about equal logic; on HBM2, CoDe decodes
a batch of 8 1.41$\times$ faster than P3-LLM-style and 1.28$\times$ faster than NPU only. Since a column's beats follow
from its period and the clock alone, the decoupling carries over to any DRAM whose column outlasts one beat.
