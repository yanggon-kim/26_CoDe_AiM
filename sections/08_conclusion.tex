\section{Conclusion}
\label{sec:conclusion}

% P:conc-summary
Skinny GEMMs keep LLM decoding memory-bound on mobile platforms and edge servers, and prior DRAM PIM paces every
multiply--accumulate (MAC) by a DRAM command and fills its idle beats with multipliers or commands. This paper argues
that DRAM timing bounds column accesses, not MACs on a latched column, so a PIM die can fill those beats with clock
cycles instead of multipliers. CoDe decouples MAC timing from DRAM command timing: one column read feeds many
processing-unit beats over a tile of tokens, so each weight column is read once per tile instead of once per token. On LPDDR5-6400, CoDe returns 1.87$\times$ the wider-PU LP-Spec-style's
tokens per second per logic mm$^2$; on HBM2, CoDe decodes a batch of 8 1.24$\times$ faster than the faster-PU
P3-LLM-style for 0.59\,\% more of the stack's area. Since a column's beats follow
from its period and the clock alone, the decoupling carries over to any DRAM whose column outlasts one beat.
