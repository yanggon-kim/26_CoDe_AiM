\begin{abstract}
% P:abs-summary
Large language model decoding on mobile platforms and edge servers runs skinny GEMMs: with speculative decoding or small
batches, each weight matrix meets 2 to 32 tokens, and the host stays memory-bound. DRAM processing-in-memory (PIM) offers the bandwidth, but
its processing units (PUs) run one multiply--accumulate (MAC) beat per column command, so their compute serves one
token. Prior designs keep every MAC paced by a DRAM command: LP-Spec widens each command's
MAC step with 4$\times$ the multipliers, and P3-LLM's command per token caps a read at two tokens. We observe that
DRAM timing bounds column accesses, not MACs on a latched column: a 5\,ns LPDDR5-6400 or 4\,ns HBM2 column fits four
PU beats at 0.8--1\,GHz. We propose CoDe (Command-Decoupled PIM): one
command delivers a weight column, which the PU applies to a tile of tokens at its own clock. On each rival's memory, workload and precision, CoDe reaches LP-Spec-style's
decoding speed on a mobile platform with the stock multiplier count clocked at 0.8\,GHz, on 0.539$\times$ its logic area; built as published, with
one unit per two banks, LP-Spec-style takes 0.96$\times$ CoDe's logic, and CoDe decodes 1.49$\times$ faster. On HBM2, CoDe
decodes a batch of 8 1.68$\times$ faster than P3-LLM-style and 1.28$\times$ faster than NPU only, which P3-LLM falls back
to at that batch.
\end{abstract}
