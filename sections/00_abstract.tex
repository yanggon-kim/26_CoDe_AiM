\begin{abstract}
% P:abs-summary
Speculative decoding and small-batch serving are widely used for large language model decoding on mobile platforms and
edge servers, and both turn decoding's GEMVs into skinny GEMMs. Although each weight matrix now meets 2 to 32 tokens,
these GEMMs remain memory-bound on the host. Such GEMMs suit DRAM processing-in-memory (PIM), which offers the bandwidth
they need. However, stock PIM was designed for GEMVs, so its MAC throughput falls short on skinny GEMMs. In this work, we
first conduct a detailed characterization of stock PIM's GEMM time, which shows that useful MACs fill only
14.1--19.1\,\% of that time. Two root causes take the rest: non-MAC DRAM commands that stall every MAC
(23.4--43.7\,\%) and idle MAC beats (42.2--57.4\,\%). Both causes arise because a DRAM command paces every MAC, a choice
that suits GEMVs but not GEMMs. Prior PIM designs fill the idle beats at a cost: four times the multipliers, in a die that builds logic ten times less
densely than an ASIC, or one command per token, which lets a column read serve at most two tokens. DRAM timing, however,
bounds how often a column is read, not how many MACs may consume it, and an all-bank column already spans four
command-clock cycles. Based on this characterization, we propose CoDe (Command-Decoupled PIM), which decouples MACs from DRAM
commands without adding multipliers, with one technique per root cause. Row reuse removes the repeated non-MAC
commands: a tile of tokens shares one row sweep, so each weight column is read and each row switch is paid once per
tile rather than once per token. Beat filling removes the idle beats: the PU, clocked at the command clock, computes
the tile's tokens in all four beats of each column period from the latched column. On a mobile platform, CoDe returns 1.87$\times$ LP-Spec-style's tokens per second per logic mm$^2$
and decodes 1.60$\times$ faster at about the same logic area. On an HBM2 edge server, CoDe decodes a batch of 8
1.41$\times$ faster than P3-LLM-style and 1.28$\times$ faster than NPU only.
\end{abstract}
